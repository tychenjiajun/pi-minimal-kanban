Owner: product designer. Spec, in `docs/product/design-v0.2.md`, the exact wording and format for:

1. **Board briefing** (backlog #3): the block `kanban_list` returns to onboard a new agent — workflow summary, the claim rule, terminal releases the claim, `force` is a deliberate takeover, handles are self-asserted, and the recommended first calls. Must fit in <= 20 lines.
2. **Task row format** (backlog #4, #7): include task id, status, title, assignee with claim age (`@coder-1 3d`), and `rev`. Show the exact rendering including truncation.
3. **Truncation + paging copy** (backlog #4): what `limit`/`offset` print when rows are omitted, and what `summary: true` prints.
4. **Stale claim surface** (backlog #1): how claim age appears on `/kanban`, in `validate` (`stale_claim` threshold default 24h, overridable), and in the `wrong_owner` error text. Include the exact sentence naming the release call.
5. **`/kanban release <id>`** copy: the confirmation prompt, success text, and refusal when the task is not claimed.
6. **`/kanban help`** text: claim rule, terminal-status rule, handle convention, in <= 12 lines.

Rules: respect GLOSSARY vocabulary; plain ASCII except the existing markers (◆ ◇ ─ · ⚠); no emoji beyond ⚠; the briefing must be copy-pasteable into a tool's text output.

- [ ] Every example fits the default 76-column render width.
- [ ] The briefing names the initial status, every active status, and the `force` rule.
- [ ] No source file is modified.
