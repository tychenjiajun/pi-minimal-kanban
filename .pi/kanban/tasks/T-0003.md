## Adversarial review (T-0003) — fix-then-merge

The briefing text itself is exact; the empty-board *trigger* and the structured mirror are wrong, and the status-line overflow branch is not the specified one.

1. **P1 — `src/index.ts:370-386` (+ `src/render.ts:461`): the briefing branch hides unreadable task files.** Verified: board with one file `T-0001.md` = `junk\n` → `kanban_list` returns the onboarding briefing, `total: 0`, and `text` never mentions the file (only `structuredContent.fileErrors` does). The agent is told the board is empty when it is corrupt. Fix: require `board.fileErrors.length === 0` for the empty-board trigger and prepend `renderFileErrors(..., { mode: "both" })` to the briefing text. (Same root cause as the T-0005 finding; one fix closes both.)

2. **P1 — `src/index.ts:380-386`: the briefing's `structuredContent` hard-codes `total: 0, offset: 0, limit: 0, returned: 0, hasMore: false`.** On a board with tasks, `kanban_list {briefing: true}` — the call the briefing itself recommends as "start here" — reports `total: 0` / `hasMore: false`. Any consumer that decides "is there work?" from `total` gets "empty board". Design §1 only requires the `briefing` string mirror, and every paging field is `Optional` in `ListOutput`. Fix: omit the paging fields for the briefing, or set `total: board.tasks.length`. (`limit: 0` is also below the parameter's own declared minimum of 1 — a read-back-and-echo fails validation.)

3. **P1 — `src/render.ts:449-453`: the >74-column fallback prints one status, not "the first eight".** Verified with realistic ids: `  other  ◇ backlog-refinement  (+9 more)` — eight status ids the design says to print are hidden. Design §1: "If the line would exceed 74 characters, keep the first eight and append `  (+N more)`". Fix: build the cell list incrementally so as many cells as fit are kept, then append `  (+N more)`; fall back to a single cell only when not even two fit.

4. **P2 — `src/index.ts:370`: the trigger ignores `summary` and `includeTerminal`,** so `kanban_list {summary: true}` on an empty board returns the briefing rather than a zero-count summary. Defensible (design §3: "Zero tasks on the whole board is the briefing"), but say so in the tool description/`prompt` text so the tester does not read it as a bug.

**AC status:** met, with the caveats above. `briefing: true` returns the §1 template verbatim — 18 lines, 74-column maximum, exact claim/terminal/self-asserted-handle/first-call wording, `Board  <dir>` via `displayPath` with the 69/`...`-66 rule, `Workflow  <name>  ·  initial: <initial>` with `(unnamed)` fallback, `◆`/`◇`/` (terminal)`/two-space joins in workflow order; it wins over `task`, `limit`, `offset`, and `summary`; the mirror `structuredContent.briefing === text`; missing workflow → the single `Workflow  unavailable  (⚠ run /kanban validate)` line with the rest unchanged (a pre-existing test was updated rather than deleted, and its comment explains why); no active status → `  active  (none - exclusivity rests on kanban_assign)`; a *filtered* empty result still prints `No matching tasks.`; all five tools' `promptGuidelines` state their rule; README documents `briefing: true` and the empty-board behaviour.

**Test honesty (P2):** `list-surface.test.ts` asserts `lines.length` is between 10 and 20 instead of the spec's 18, and never exercises the `(+N more)` branch or a board whose only file is unreadable — which is why findings 1-3 passed. Given the briefing is spec-literal output, assert the exact 18-line string for the fixture workflow.
