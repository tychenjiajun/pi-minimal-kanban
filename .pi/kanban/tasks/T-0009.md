Reviewer P1 findings on T-0003/T-0004/T-0006. Implement per `docs/product/design-v0.2.md`.

- [ ] Briefing path must not hide unreadable files: when a board has `fileErrors`, the briefing response still prints the warning lines and names each file, and `structuredContent.total` is the real filtered total (not 0). `briefing: true` on a 137-task board must not report `total: 0`.
- [ ] `limit` maximum is 500 everywhere: schema, clamp, README. Today the schema rejects 500 before the clamp, so the clamp is dead code. Update design §3 or the code so they agree (PM decision: implement 500).
- [ ] `wrong_owner` names the claim age in every case, including a claim held outside an active status; the release sentence stays exact per design §4.
- [ ] `/kanban validate` reports `stale_claim` for an assignment older than the threshold in a non-active status too, with wording that distinguishes an active claim from an assignment hint (this blocks moving into an active status).
- [ ] The no-claim refusal in `/kanban release` prints the real status without a drift marker (`status  new`, not `new ⚠`).
- [ ] `/kanban mine` and `/kanban status` use the §2 row format, including rev and claim age; drifted rows in `/kanban` columns use the same row format with the ` ⚠` marker.
- [ ] Title truncation strips the trailing space before `...`; a 14-character handle is not widened when truncated; the briefing's `(+N more)` cap prints the intended number of statuses.
- [ ] Tests for each bullet; `npx vitest run` and `npx tsc --noEmit` clean.
