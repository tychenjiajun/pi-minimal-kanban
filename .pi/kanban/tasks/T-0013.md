Backlog #10 (P2). In scope for v0.3.0, decided (not deferred). Reverses a v0.2 deferral, so it needs an ADR. Vocabulary: `GLOSSARY.md` (Task, Assignee, Claim, Forced assignment, Active status, Terminal status, Handle).

## Context
`assignTask` in `src/store.ts` lets any Handle assign an *unassigned* Task to a different Handle without `force`, recording a normal `assign` entry. Setting an Assignee for someone else is an act the owner never consented to, and History cannot express the difference. v0.2 deferred this ("assignment outside an active status is a hint, not a claim"). The hint model stays; only *who may write someone else's hint* changes. See `docs/product/v0.3-scope.md` § "#10 decision, in full".

## Blocking prerequisite — ADR 0009
Write `docs/adr/0009-third-party-assignment-is-forced.md` **first**, and implement the code to match it. It must record: the rule; the override (`force`); why the v0.2 objection ("a hint, not a claim") is answered and not violated; migration impact (existing boards with historic third-party `assign` entries stay valid — no data rewrite, no `rev` bump); rejected alternatives (a config flag; a warning instead of an error). Follow the shape of `docs/adr/0004` and `docs/adr/0008`.

## Acceptance criteria (from `docs/product/backlog.md` #10)
- [ ] Assigning a Task to a Handle other than the caller's requires `force`.
- [ ] The tool description and `promptGuidelines` state the rule in one sentence.
- [ ] The resulting History entry is distinguishable from a self-claim.

## Implementation notes
- `src/store.ts` `assignTask`: in the branch where `current` is null (or, more generally, whenever `wanted !== agent` and the caller does not already hold the Assignee), require `input.force`. Without it, throw `KanbanError("wrong_owner", …)` with a hint naming `force: true` and the exact call shape — reuse the existing `wrong_owner` code so no new code has to be taught; state this choice in the ADR.
- With `force`, record `{ action: "force-assign", by: agent, assignee: wanted, forced: true }` — the same entry the "take from another handle" path already writes. That makes it distinguishable from a self-claim with no new action name.
- Keep behavior unchanged for: assigning to yourself, clearing your own assignment, and clearing another Handle's with `force` (existing `wrong_owner` path). After this change the rule is uniform: any write to an Assignee that is not yours, in either direction, needs `force`.
- `src/index.ts`: `kanban_assign` `promptGuidelines` gains one sentence stating the rule. Keep the existing "A task has at most one assignee" guideline or merge it, do not drop the `expectedRev` one.
- `src/command.ts` `USAGE`: extend the claim/handle block with the assignment sentence. Keep the 10-line budget.
- `experimental`/compat: this is a **behavior change** — it must be called out under "Compatibility" in the 0.3.0 CHANGELOG section.

## Tests to add
`src/test/claims.test.ts`: (a) `assignTask` to another handle without `force` throws `wrong_owner` and the task file is byte-identical afterwards; (b) with `force: true` it succeeds and the history's last entry has `action: "force-assign"` and `forced: true`; (c) self-assign and self-unassign need no `force` and record `assign`/`unassign`; (d) a pre-existing task file containing a third-party `assign` entry still validates `ok: true`.
