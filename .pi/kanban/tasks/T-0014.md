Backlog #12a (P2). In scope for v0.3.0. Vocabulary: `GLOSSARY.md` (Board, Task, Task ID, Handle, Assignee, Claim).

## Context
`completeKanbanCommand` in `src/command.ts` says "Argument completions: subcommands, then task ids" but returns only subcommands. `/kanban mine <handle>` and `/kanban <task-id>` are therefore pure recall. The `USAGE` constant already states the Claim rule, the Terminal-status rule, and the Handle convention, so **do not rewrite those three** — the audit's "states no rules" is out of date (recorded in `docs/product/v0.3-scope.md`).

## Hard constraint (do not design around it, design for it)
`pi.registerCommand`'s `getArgumentCompletions?: (argumentPrefix: string) => AutocompleteItem[] | null | Promise<…>` receives **only the prefix** — no `cwd`, no `ExtensionCommandContext`. `resolveBoard({ cwd: ctx.cwd })` is unavailable at completion time. See `RegisteredCommand` in `@earendil-works/pi-coding-agent` `dist/core/extensions/types.d.ts`.

Therefore the accepted design is:
1. `src/index.ts` caches the Board location for the session. The command registration site already has `ctx` at session start; re-resolve on the same session/`cwd` events the factory already handles, and expose the cached `BoardLocation | undefined` to `completeKanbanCommand` via an explicit argument (e.g. `completeKanbanCommand(prefix, boardOrDir)`) so the function stays pure and testable. Do not use a module-level mutable global that tests cannot control.
2. Completions **never throw and never write**. Wrap the read in try/catch.
3. **No board / unreadable board ⇒ subcommand list only.** Never an empty list, never an exception. Never reuse a cached location after a `cwd` change without re-resolution.

## Acceptance criteria (from `docs/product/backlog.md` #12, plus the v0.3 design)
- [ ] Completions include Task IDs (with Status and title) and observed Handles.
- [ ] A test asserts completions include a Task ID present on the Board.
- [ ] With no Board, `completeKanbanCommand("")` returns the subcommand list and does not throw (test).

## Implementation notes
- `src/command.ts` `completeKanbanCommand(prefix, board?)`:
  - Subcommands first, exactly as today (prefix filter unchanged, `--` filter unchanged).
  - Task ID items: `label` = the Task ID (this is what pi inserts into the input), `description` = `<status> · <title>` (truncate the title to fit; reuse the existing title-truncation helper in `src/render.ts` if there is one).
  - Handle items: every distinct Handle observed as a current `assignee` and every distinct `by` in History, sorted, deduplicated, excluding Handles already appended as the current Assignee. Description names how many Tasks the Handle holds, e.g. `2 tasks`.
  - Filter by `prefix` case-insensitively across `T-` ids, handles, and `--` flags. Handles only when the prefix does not start with `-`.
  - Both items go through the existing `{ label, description }` shape; `src/index.ts` already maps to `{ value, label, description }`.
- Read with `readTasks(location)` (or `readBoard`), never `readTask` per id; exclude `fileErrors` silently — completions must not surface a warning.
- Keep it O(tasks) with no lock acquisition.

## Tests to add
`src/test/surface-pack.test.ts` or a new `src/test/completions.test.ts`: board with T-0001 assigned to `coder-1` ⇒ `completeKanbanCommand("T-0", board)` contains a `T-0001` label and its description contains the status; `completeKanbanCommand("coder", board)` contains `coder-1`; `completeKanbanCommand("", undefined)` equals the current subcommand count and does not throw; completions on a board with one malformed file still return the readable Task.

- `README.md` `/kanban` section: one sentence on Tab completion (task ids and handles, session Board, subcommands only without a board).
- `docs/product/backlog.md`: tick only the completion checkbox of #12 (the help checkbox belongs to the sibling task).

## For the reviewer
- The cache is per extension factory instance (one per session runtime), never module-level; `session_before_switch`/`session_shutdown` clear it and the handler re-resolves before every invocation.
- `readBoard` is used (not `readTask`), so `fileErrors` are dropped silently and no lock is taken.
- Caps are applied **after** prefix filtering, which is why `("Holder", …)` on 15 handles returns exactly 10 rather than 10-then-filtered.
- Uppercase handle casing is preserved from the first occurrence; matching and sorting are case-insensitive.
