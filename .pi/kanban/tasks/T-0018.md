## #10 decision
**Enforce `force`.** Reason: the v0.2 objection was that a non-active assignment is a "hint" — that stays true and is preserved, but *who may write another handle's hint* changes. Current behavior cannot be stated defensibly ("any handle may silently assign an unassigned task to any other handle"), and it closes a real race where two agents resolve contention by assigning to a third party invisibly. After ADR 0009 the rule becomes uniform: any Assignee write that is not yours, in either direction, needs `force`. Migration: existing boards keep historic third-party `assign` entries, no data rewrite.

## Deferred
#2 (claim enforcement in all non-terminal statuses — needs its own ADR, rewrites the ADR 0008 model), #6 (`/kanban` scale story), #8's unused `KanbanError.toJSON()`, and #4's "print the workflow only when it changed" (rejected as a requirement — output would depend on session history).

## Risks the reviewer should weigh
1. **T-0013 is a breaking behavior change** and reverses an explicit v0.2 decision. It needs the "Compatibility" CHANGELOG callout and ADR 0009, or a later reader will think it was an accident.
2. **T-0014's constraint is real and under-documented upstream**: `getArgumentCompletions(prefix)` has no `ctx`/`cwd`. The session-cached location is a design decision, not an implementation detail; if a later refactor drops the cache, completions silently go empty. The task requires a no-board test for exactly that.
3. **T-0016 `repair-ids` is the only destructive subcommand on the board.** It must take the board lock and it must never lower `counter.json` (`docs/adr/0005`). The prose-reference limitation must be in the dry-run footer, not just the README.
4. **Doc rot found (recorded in the scope doc so it is not re-litigated):** the audit says `/kanban help` "states no rules" — false, `USAGE` states all three. The audit says `src/index.ts` pre-reads the task in `kanban_move` — false, shipped in 0.2.0. Backlog #12/#13/#9 checkboxes are stale in both directions.
