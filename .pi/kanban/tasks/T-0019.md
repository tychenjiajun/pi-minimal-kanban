## Reproduction
Open `README.md`, the `/kanban` command list.

- Line 117 reads: `/kanban release <id>        release a claim (the one subcommand that writes)`
- Line 122, nine lines later, reads: `Everything renders read-only except \`release\` and \`repair-ids\`:`

The two statements contradict each other: `repair-ids --yes` also writes
(renames task files and may raise `counter.json`).

## Expected
The command list does not single out `release` as the only writing subcommand.
Suggested: `release a claim (writes; asks for --yes)`.

## Actual
A reader who scans only the command list believes the board has exactly one
writing subcommand, which was true in 0.2.0 but not after T-0016.

## Severity
post-release (documentation only; the behaviour is correct and the second
sentence is accurate). Introduced by T-0016, which added a second writing
subcommand without updating this list line.

## Evidence
`sed -n '110,125p' README.md`; `/kanban repair-ids --yes` writes
(`docs/workflow.md` and the design both describe it as destructive).
