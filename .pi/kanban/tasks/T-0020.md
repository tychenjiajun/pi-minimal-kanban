## Reproduction
`README.md` line ~134:

> Tab completion lists the subcommands, the task ids on this session's board
> (with status and title), and **every handle the board has seen**; with no board
> it completes only the subcommands.

The implementation caps handles at 10 and task ids at 20
(`src/command.ts`: `MAX_COMPLETION_TASKS = 20`, `MAX_COMPLETION_HANDLES = 10`,
`docs/product/design-v0.3.md` §3.3).

Reproduced on a scratch board with 15 distinct handles: `completeKanbanCommand("")`
returns 10 handle items, silently dropping 5. On 25 tasks, `T-0` returns 20.

## Expected
The README states the caps (or says "up to 10 handles / 20 task ids"). The
design already describes caps as a stated bound; the README should not promise
"every handle".

## Actual
An agent trusting the README assumes a handle absent from the dropdown is
unknown to the board, when it may simply be beyond the cap.

## Severity
post-release (documentation only; behaviour matches the design).

## Evidence
`docs/product/design-v0.3.md` §3.3 "Order, caps, dedup"; scratch board with 15
handles yields 10 completion items.
