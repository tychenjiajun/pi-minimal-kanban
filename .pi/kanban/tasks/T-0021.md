## Reproduction
Point a board at an absolute path that is NOT under the session cwd (e.g. a
`project` tool argument or `PI_KANBAN_DIR`), then read any `/kanban` header or
the board briefing.

Scratch board `/tmp/qa-boards/walk-a`, cwd `/Users/.../pi-minimal-kanban`:

- `/kanban` header prints `tmp/qa-boards/walk-a/.pi/kanban`
- `kanban_list {briefing:true}` prints `Board  tmp/qa-boards/walk-a/.pi/kanban`

`src/paths.ts`:
```ts
export function displayPath(path, cwd) {
  const rel = path.startsWith(cwd) ? path.slice(cwd.length) : path;
  return rel.replace(/^[/\\]/, "") || ".";   // strips the leading / of an absolute path
}
```

## Expected
A path outside cwd stays absolute: `/tmp/qa-boards/walk-a/.pi/kanban`.

## Actual
The leading `/` is stripped from every path, so an absolute board outside cwd
renders as a relative-looking `tmp/...`, which cannot be passed back to a tool
or `cd`'d into. It looks like a board inside the cwd that does not exist.

## Severity
post-release (cosmetic/UX; no data effect). Pre-existing in 0.2.0
(`git blame` -> d65fd66), not introduced by v0.3, but it is visible on the v0.3
`validate`/`repair-ids` headers too.

## Evidence
`displayPath("/tmp/x/.pi/kanban", "/Users/me/app")` returns `tmp/x/.pi/kanban`.
`docs/product/design-v0.3.md` §5.2 says `<dir>` is `displayPath(plan.dir, cwd)`.
